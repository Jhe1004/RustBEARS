# RustBEARS v1.2 implementation contract

Accepted on 2026-11-15 following the v3 proposal review. This amendment takes
precedence over conflicting wording in the v3 proposal. The user authorized
implementation of the full plan; gates determine when later stages may begin.

## Probability and compatibility

1. Preserve the existing state index order (range size, then combination order).
   Canonical state labels identify states; they do not reorder legacy sampling.
2. Separate root likelihood weights from normalized root sampling probabilities.
   Contract C retains the legacy all-one nonempty weights and their scale.
   Contracts A and B use normalized priors. Record the log weight scale.
   Reject negative/nonfinite/zero-total weights and mismatched labels.
3. First release root modes are uniform_nonnull, custom_weights, and
   legacy_flat_weights. No equilibrium_stationary mode is promised.
4. Contract B completes the empty ancestor kernel with C(0;0,0)=1. Contract A
   subtracts the log probability that all tips are nonempty. Contract C retains
   the historical score and is labeled as such.
5. Simulation inherits A/B from the fitted model. C requires an explicit
   simulation_conditioning. Bootstrap records both scoring and generating
   contracts. Changing the scoring contract requires observed-data refitting.
6. All C profile intervals are support intervals. The first release may reject
   C bootstrap_plugin rather than silently assign a generating distribution.

## Gate 1 acceptance

The scope remains single-layer DEC/DEC+J, fixed state space and rooted binary
trees. Tier-1b expansion and large server calibration wait for Gate 1 evidence.

- Three-tip pure extinction analytic reference and exhaustive A/B normalization.
- Six predeclared distributions, N=1,000,000 simulator draws per distribution,
  R=9,999 exact multinomial reference frequency vectors. TVD and G2 produce
  twelve tests controlled jointly by Holm at family alpha=0.01. A maximum-TVD
  plot is diagnostic only, not an additional rejection rule.
- Fault-positive controls use predeclared configurations with a demonstrable
  nonzero distribution difference. Report detection counts and exact binomial
  uncertainty, not a universal claim inferred from 99/100. Fix random seeds in
  the experiment configuration; do not change them to obtain a pass.
- Report deterministic correctness, random goodness-of-fit, and fault-detection
  sensitivity separately. A pending or failed experiment is never a PASS.

## Later-stage requirements

- Domain-separated random task identities include generating model, simulation
  purpose, outer bootstrap replicate, inner replicate, tree, map, layer and step.
  State index bounds and RNG versions explicitly. Do not claim an unbounded
  collision-free 64-bit encoding. Preserve the legacy stream as a separate mode.
- Checkpoint fingerprints cover the complete canonical model/task configuration,
  including fixed parameters, links, observations, tree data, summary mapping,
  root/likelihood/simulation contracts and RNG version. Save complete event
  histories, or validate deterministic regeneration from saved complete inputs.
- Missing bootstrap fits produce failure bounds and a separately identified
  Monte Carlo interval envelope: CP lower(r,B), CP upper(r+failed,B).
- Fixed tree sample is the default diagnostic target. Population inference
  requires explicit independent/MCMC provenance; compute ESS for each scalar
  event summary, route and paired route difference.
- Route intervals are approximate per-comparison exploratory diagnostics, with
  no unvalidated familywise or selection-after-ranking coverage promise.
- Missing-tree summaries label their complete-case scope. Do not apply bounded
  probability missing-mass arguments to unbounded BSM event counts.

## Protected assets and delivery

The pre-v1.2 repository is tagged v1.1.4-baseline (52528c7). Stages 04 through 14,
16 and 17 and external source data remain read-only. Frozen checksums and actual
validation records are held in ../19_RustBEARS_v1_2_开发与验证_20261115/evidence/.

The complete deliverable includes native Rust and R/Python APIs, four uncertainty
modules, independent validation and calibration, benchmarks, tutorials, figures,
manuscript and reproducible archive packages. Publication/remote service outcomes
must be recorded from actual results; an archive preparation is not a DOI deposit,
and a CI configuration is not evidence of successful execution on another OS.
